# La description del skill

## Lecciones

- **La `description` del frontmatter declara la razón de ser del skill (el para qué), no el procedimiento (el qué hace paso a paso).** Por qué: la description de `gestionar-piezas` salió enumerando sus operaciones (captura, promueve, mueve por el kanban) y el usuario lo corrigió — el patrón de la casa es «X sobre Y para que Z» (`actualizar-artefactos`: «para que los consumidores deleguen la mutación»; `consultar-decisiones`: «para que el trabajo las respete»). El procedimiento vive en el cuerpo; la description es lo que un lector —humano o agente— usa para decidir si invocar, y la razón de ser es lo que informa esa decisión.
